# Ежедневный обзор рынка Forex

Проект: EURUSD, GBPUSD, USDCHF. Прогноз утром, разбор вечером, сводка в конце недели.

## Структура

```
market-review/
  README.md          - этот файл, методология
  sources.md         - рейтинг доверия к источникам
  scoreboard.md      - таблица точности всех прогнозов
  forecast/
    YYYY-MM-DD.json  - авторская копия уровней, файл на день (живая лежит в data/forecast/ приложения)
  YYYY-MM-DD/
    00-market-snapshot.md   - факты на утро: котировки, ставки, что вышло
    01-forecast-day.md      - прогноз до конца дня
    02-forecast-week.md     - прогноз до конца недели
    03-review-day.md        - вечером: что сбылось, что нет, почему
  YYYY-Www/
    weekly-review.md        - в пятницу вечером: разбор недели
```

## Уровни на графике

Каждый уровень из прогноза дублируется в файл дня `forecast/YYYY-MM-DD.json` и рисуется в FXViewer:
горизонтальная линия цвета пары от момента прогноза до его горизонта, диапазон -
двумя линиями с полупрозрачной заливкой между ними. Кружок в начале линии открывает
попап с автором, обоснованием и источником.

Это не индикатор - добавлять ничего не нужно. В панели символов есть строка
**Forecast** сразу под **Calendar**: клик включает и выключает слой, правый клик -
`Reload forecasts` (перечитать файл без перезапуска). Пары фильтруются сами собой:
если пара скрыта в панели, её прогнозы не рисуются.

Формат файла и поведение слоя описаны в
[docs/forecast-indicator.md](../docs/forecast-indicator.md).

**Два места хранения.** Приложение читает все `*.json` из папки `<exe>/data/forecast/`
и склеивает их в один список. Авторские копии лежат в git в `market-review/forecast/`,
по файлу на день (`YYYY-MM-DD.json` - дата, когда прогнозы сделаны; формат внутри
одинаковый). После правки прогнозов копии нужно положить в базу:

```bash
cp market-review/forecast/*.json FXViewer/bin/Debug/net10.0-windows/data/forecast/
```

Потом правый клик по строке Forecast -> Reload forecasts.

В файл попадают не только мои прогнозы, но и чужие (`Author`: RoboForex,
TradingEconomics и т.д.). Через несколько недель на графике будет прямо видно,
кто из источников попадал, а кто нет.

## Правило источника для каждого уровня

**Ни одно число в прогнозе не появляется без указания, откуда оно взято.**
Допустимы ровно два типа происхождения:

- **Источник** - число опубликовано внешним источником. Обязательны: название,
  дата публикации, ссылка. Пример: "1.1675 - максимум с конца мая, Forex Today
  tmgm от 19.08.2026".
- **Мой расчёт** - число выведено мной. Обязательны: точка отсчёта и способ вывода.
  Пример: "1.1722 = спот 1.1706 плюс 16 пипсов, половина дневного прироста".

Почему это важно: за уровень из источника отвечает источник, и ошибка означает,
что источнику нельзя доверять. За свой расчёт отвечаю я, и ошибка означает, что
метод плохой. Это разные выводы, и без пометки происхождения их не разделить.

В файлах `forecast/` за это отвечают два разных поля: `Basis` (почему такой уровень)
и `Source` (откуда само число). Записи без `Source` считаются браком.

## Правило якоря (введено 22.08.2026)

**Расчётные числа прогноза не должны зависеть от того, в какую минуту составлен
прогноз.** Формулы вида "спот на 10:30 плюс N пипсов" запрещены: часом раньше
или позже они дают другой уровень. Допустимые якоря: вчерашний дневной бар
(граница 21:00 UTC летом), бар прошлой недели, ADR, круглые уровни, 200-дневная MA,
опубликованные внешние уровни, страйки экспайри. Спот записывается только справочно.

Полная методология уровней - формулы пивотов, ADR, ежедневный чек-лист сбора
чужих уровней, скоринг пост-фактум - в [levels.md](levels.md). Своя сетка
считается скриптом:

```bash
python market-review/tools/levels.py
```

## Регламент дня

**Утро (до 11:00 UTC).** Сначала `tools/levels.py` (своя сетка от вчерашнего бара)
и сбор внешних уровней по чек-листу из [levels.md](levels.md). Потом снимок рынка
и прогноз на день и на остаток недели.
Прогноз всегда содержит числа, иначе его нельзя проверить:

- точка на закрытие дня (17:00 New York = 21:00 UTC),
- ожидаемый диапазон дня (low / high),
- три сценария с вероятностями: база / бычий / медвежий,
- уровни-триггеры: что должно случиться, чтобы сценарий сменился,
- условие опровержения - при каком уровне прогноз считается ошибочным.

**Вечер (после 21:00 UTC).** Разбор:

- факт против прогноза по каждой паре, в пипсах,
- любое движение больше 40 пипсов за час получает объяснение с привязкой ко времени и к новости,
- если объяснения нет - так и пишем "причина не найдена". Это честнее, чем придумывать,
- каждый уровень дня (свой и чужой) получает исход TOUCH / BOUNCE / BREAK /
  NOT_TESTED по правилам из [levels.md](levels.md) - из этого копится рейтинг
  источников в sources.md.

**Пятница вечером.** Недельный разбор: все движения, точность прогнозов за неделю,
какие источники сработали, какие подвели.

## Как считается точность

Три метрики на каждую пару в день:

| Метрика | Что значит | Зачёт |
|---|---|---|
| Направление | угадан знак движения (close vs открытие прогноза) | да / нет |
| Диапазон | факт high/low уложился в прогнозный диапазон | да / частично / нет |
| Точка | ошибка точки прогноза в пипсах | < 20 пипсов = хорошо, 20-50 = средне, > 50 = мимо |

Плюс отдельно: **какой сценарий из трёх реализовался** и **сработал ли триггер**.

Ошибка в пипсах считается: EURUSD и GBPUSD - 4-й знак (0.0001 = 1 пипс),
USDCHF - 4-й знак (0.0001 = 1 пипс).

Каждый оценённый прогноз дополнительно пишется строкой в машиночитаемый лог
[results.csv](results.csv) - по строке на точку, диапазон и сценарий, с фактами,
ошибкой, направлением и расстояниями точки до закрытия и до экстремумов окна
(dist_close/dist_high/dist_low). scoreboard.md - витрина для чтения, results.csv -
данные для статистики: калибровка вероятностей, распределение ошибок,
систематические сдвиги. Заполняется вечером вместе с разбором.

## Принципы

1. **Прогноз без числа - не прогноз.** "Возможен рост" не засчитывается.
2. **Каждое сильное движение объясняется по времени.** Сначала находим минуту движения,
   потом ищем новость этой минуты. Не наоборот - иначе получается подгонка.
3. **Разделяем "рынок так думал" и "я так думал".** Если консенсус был неправ - это
   не оправдание, но это другой тип ошибки, чем "я пошёл против консенсуса и проиграл".
4. **Позиционирование важнее прогноза.** Когда рынок уже стоит в одну сторону,
   новость той же направленности двигает цену слабо, а противоположная - сильно.
5. **Признаём незнание.** Если причина движения неизвестна - пишем это прямо.
